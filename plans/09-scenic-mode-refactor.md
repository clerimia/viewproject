# 09 前端去通用客服化与导览模式改造

## 目标

弱化当前通用客服/Agent 工具产品的痕迹，将前端交互模式统一改造成景区导览场景。

## 当前情况

前端仍有：

- 普通对话
- 智能 Agent
- Agent 任务模式
- 查询余额、分析数据等通用业务文案

这些内容与景区导览产品不一致。

## 涉及文件

- `src/main/resources/static/index.html`

## 方案选择

### 方案 A：保留 Agent 能力但改名

将：

- 普通对话 → 景区问答
- 智能 Agent → 智能导览规划

适合想保留 Agent 技术展示时使用。

### 方案 B：隐藏 Agent 模式

只保留主聊天体验，避免演示时误入通用 Agent 逻辑。

适合比赛演示和产品交付。

## 推荐方案

优先采用方案 B 或轻量方案 A。

## 实施步骤

### 步骤 1：替换侧边栏模式文案

```text
普通对话 → 景区问答
智能 Agent → 路线规划
```

或直接隐藏 Agent 按钮。

### 步骤 2：替换顶部标题

```text
普通问答 (Qwen) → 云隐山智能导览
Agent 任务模式 (思考 + 工具调用) → 智能路线规划
```

### 步骤 3：替换欢迎语

删除：

```text
查询余额、分析数据
```

改为：

```text
我可以帮你讲解景点、推荐路线、查询服务设施和介绍美食特产。
```

### 步骤 4：如保留 Agent 模式，限定场景

Agent 模式应只做：

- 半日游路线规划
- 亲子游路线规划
- 历史文化游路线规划
- 美食路线规划

不要出现通用工具调用文案。

## 验收标准

1. 页面上不再出现“客服”“余额”“通用 Agent”等与景区无关文案。
2. 所有模式名称都围绕景区导览。
3. 演示路径清晰，不会让评委误以为是通用聊天机器人。

## 风险点

- 如果直接删除 Agent 模式，要确认相关代码没有依赖当前按钮。
- 如果保留 Agent 模式，后端 Agent 能力也应避免返回通用业务内容。
